# Development toolchain, exact-pinned.
#
# Why pinned: a lint gate whose verdict depends on the day it runs cannot tell you whether your
# change is clean. In a sibling repository CI resolved ruff at install time; when a minor release
# widened the default rule set, CI started reporting findings on code that had not changed while a
# developer on the previous version saw "All checks passed".
#
# Bump deliberately: change the version here, run `make lint`, fix what the new version finds, and
# commit both together. `make python` warns when the installed ruff differs from this file, because
# a local pass with a different version does not predict CI.
#
# The validators in tools/ are stdlib-only by design and need nothing from this file.
ruff==0.15.20
pytest==9.1.1
cfn-lint==1.52.1
# zizmor audits the workflow files themselves. Pinned for the same reason as the rest: its rule set
# grows, and an unpinned install would turn the gate red with no commit behind it. The consequence of
# pinning is that a new rule does not reach us until the pin moves, which is why the workflow also
# runs on a schedule — see .github/workflows/zizmor.yml.
zizmor==1.30.0
# checkov scans the CloudFormation and the workflow files for security posture, which cfn-lint has no
# opinion about: cfn-lint proves a template is well formed, not that a function is unbounded or a
# secret unencrypted. Pinned for the same reason as the rest, and with the same consequence -- a new
# policy does not reach us until the pin moves. It is a heavy install (a large transitive tree), so
# `make iac-security` skips with a message when it is absent rather than failing, the way the
# gitleaks and markdownlint targets do for the tools that are not pip-installable.
#
# Findings are triaged in the templates with `# checkov:skip=<id>: <reason>`. A skip without a reason
# is rejected by tests/test_iac_security.py, because an unexplained skip is how a scanner goes quiet.
checkov==3.3.16
