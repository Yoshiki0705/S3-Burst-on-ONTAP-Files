# 評価段階の付与ルール — TR 統合

このドキュメントは、Technical Report（TR）由来の記述に評価段階を付けるときの規則を定める。
要件 3「評価段階の厳密な区別」に対応する。段階の定義そのものは[検証状況](../../verification-status.md)が
唯一の出所であり、ここでは再定義しない。本ドキュメントは、その 4 段階を TR 統合の文脈でどう付与
するかの適用規則だけを持つ。

> **段階を再定義しない理由**: 段階の定義を 2 か所に置くと、片方だけが更新されて古い側が新しい側を
> 上書きする。[検証状況](../../verification-status.md)の表を正とし、本ドキュメントはそこへ付与規則で
> 接続する。

## 4 段階（定義は検証状況が本体）

| 段階 | TR 統合での付与対象 |
|---|---|
| 検証済み | この構成で実測し、環境を併記できる主張のみ |
| ドキュメント記載 | TR または AWS/ベンダー公式ドキュメントに記載があり、出典を付せる主張。実機では確かめていない |
| 未検証 | 記載はあるが、この構成では実機で追っていない |
| 未確認 | 公開ドキュメントに記載を見つけられていない。「できない」ではない |

## 付与規則

### TR のチューニング指針 = ドキュメント記載 + 出典 3 項目（要件 3.2）

TR のチューニング指針を記述するときは「ドキュメント記載」段階とし、次の 3 項目を出典として併記する。

| 出典項目 | 内容 |
|---|---|
| TR 名 | 文書名（例: `High File Count NAS Workloads`） |
| 版または発行日 | 版番号または発行日 |
| 該当節見出しまたは節番号 | 節見出しまたは節番号（例: `§3.2`） |

該当節見出しまたは節番号を特定できない場合は、「ドキュメント記載」として引用せず、参照した TR 名と
探索済みの範囲を明示したうえで段階を「未確認」とする（要件 3.3）。

### ベンチマーク数値 = 環境 7 項目併記（要件 3.5）

ベンチマーク数値を記述するときは、次の 7 項目をすべて併記する。1 項目以上が記録されていない数値は、
版付きの主張として引用せず、記録されていない項目を項目名で列挙する（要件 3.6）。

| 環境項目 |
|---|
| 測定日 |
| リージョン |
| ONTAP バージョン |
| ファイルシステム構成 |
| オブジェクトサイズ |
| 並列度 |
| 測定対象 |

> **版付き主張の抑止**: [検証状況](../../verification-status.md)には、ONTAP バージョンを記録し忘れた
> ために「この ONTAP 版で取得できる」とは書けず「この日のこの構成で取得できた」までしか書けない
> 実例がある。7 項目のうち 1 つでも欠ければ版付き主張にできない、という既存の運用に合わせる。

### プロジェクト固有の性能主張で実測値がないとき（要件 3.4）

実測値が存在しない性能主張は記述せず、未計測セクション（公開物の「## まだ測っていないこと」節）に
次の 3 項目を記録し、既存の主張データを変更しない。

| 未計測セクションの記録項目 |
|---|
| 主張の対象 |
| 測定していない旨 |
| 測定に要する最小構成 |

### 公開ドキュメントに記載を見つけられないとき（要件 3.7）

「できない」「未対応」と記述せず、「未確認」と記述したうえで探索済みの公開ドキュメント範囲を併記
する。[検証状況](../../verification-status.md)の「未確認と判定する前に開くページ」に従い、機能一覧・
API 対応表・制限/クォータ・操作手順・撤去手順を開いてから判定する。

## 既存成果物への適用確認

本イニシアチブで作成済みの台帳に、上記の付与規則が適用されているかを確認した。

| 成果物 | 評価段階に関わる記述 | 適用状況 |
|---|---|---|
| [スコープ台帳](scope-ledger.md) | スコープ判定であって技術的主張の段階付与ではない | 段階付与の対象外（スコープの内外のみを記録）。付与規則は非適用で正しい |
| [委任台帳](delegation-ledger.md) | 委任判定であって技術的主張の段階付与ではない | 段階付与の対象外（作業主体の判定のみを記録）。付与規則は非適用で正しい |
| [差分論点台帳](divergence-ledger.md) | 差分論点に status（確定済み / 未完了 / 未確認）を付与 | 確定済みは TR 側参照と FSx for ONTAP 側出典の双方がそろう論点のみ。未確認論点は断定形を使わず「可能性がある」表現に留めている（要件 3.7・7.3 と整合）。確定済みの出典は既存の検証記録・公式ドキュメント URL を併記済み |

> **差分論点の status と評価段階の関係**: 差分論点台帳の `status` は差分論点に固有の分類（確定済み /
> 未完了 / 未確認）であり、4 段階（検証済み / ドキュメント記載 / 未検証 / 未確認）とは別の軸である。
> ただし「未確認」で断定形を使わないという規律は両者で共通する。差分論点が参照する FSx for ONTAP 側
> 出典（実測記録・公式ドキュメント）の評価段階は、[検証状況](../../verification-status.md)が本体である。

## TR チューニング指針を Spoke 側に書くときの手順

委任台帳で Spoke 判定になった知見（この構成固有の手順・検証）について TR のチューニング指針を引用
するときは、次の順で付与する。

1. TR 本文で該当節見出しまたは節番号を特定する。特定できなければ段階を「未確認」とし、探索済み範囲を
   併記する（規則の「チューニング指針」節）。
2. 特定できたら段階を「ドキュメント記載」とし、出典 3 項目（TR 名・版/発行日・節）を併記する。
3. この構成で実測した値を併記する場合は、別途「検証済み」として環境 7 項目を併記する。TR の記載と
   実測は別の段階として分けて書き、「ドキュメントに記載がある」を「実機で動く」として引用しない。

Hub 判定になった知見（横断的な採用判断材料）の本体記述は Hub 側で行うため、本 repo では段階付与の
対象にしない（委任の引き渡しは別タスク）。
