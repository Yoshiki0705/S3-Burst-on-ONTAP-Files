# スコープ台帳 — TR 群のスコープ判定記録

この台帳は、NetApp ONTAP の Technical Report（TR）群について、本イニシアチブで読み込み対象と
するかどうかの判定を 1 本 1 行で記録したものである。要件 1「対象 TR スコープの決定」に対応する。
段階の定義は[検証状況](../../verification-status.md)にあるが、この台帳が記録するのはスコープの
内外であって、技術的主張の評価段階ではない（評価段階の付与は後続の別タスク）。

対象は入力資料 18 本の TR（PDF）。18 本すべてに「スコープ内」または「スコープ外」のいずれか一方の
判定が付き、未判定は 0 件である（要件 1.1）。内訳は、優先スコープ 7 本・後続スコープ 3 本・
スコープ外 8 本。スコープ内 10 本は優先 7 本と後続 3 本の和である（要件 1.2）。

列構成は次のとおり。ファイル名は入力資料の literal なファイル名をそのまま記載する。委任判定列は
後続タスクで付与するため、本時点ではプレースホルダ（`—（タスク3で付与）`）を置く。

| 列 | 内容 |
|---|---|
| ファイル名 | 入力 TR の PDF ファイル名（要件 1.1、1.4） |
| スコープ判定 | スコープ内 / スコープ外 のいずれか一方（要件 1.1） |
| 優先・後続区分 | スコープ内の TR は 優先スコープ / 後続スコープ のいずれか一方。スコープ外は `—`（要件 1.2） |
| 関連根拠 | この構成（S3 API 収集 → FSx for ONTAP origin → FlexCache で NFS/SMB 配布）との関連を述べる 1 文（要件 1.3） |
| 委任判定 | 知見ごとに Hub / Spoke / 保留 に分かれるため、TR 単位ではなく[委任台帳](delegation-ledger.md)を参照する（§委任判定列の付与時期） |

## 委任判定列の付与時期

委任判定（Hub / Spoke / 保留）は、スコープ判定とは直交する独立した分類であり、[委任台帳](delegation-ledger.md)に
記録済みである。委任判定は TR 単位ではなく知見単位で付くため、1 本の TR から複数の知見が別々の
判定を受けうる。このためスコープ台帳の委任判定列は単一値を持たず、委任台帳への参照とする。各知見の
判定根拠・配置先 repo・参照リンクは委任台帳が本体である。

## スコープ外から参照する場合の区分変更記録

スコープ外とした TR の内容を後に参照する必要が生じた場合は、当該 TR の区分を「スコープ外」から
「スコープ内」へ変更した記録を残したうえで参照する（要件 1.6）。変更記録には、変更対象の TR 名と
変更後の区分の 2 項目を含める。既存のスコープ判定行は上書きせず、下の記録表に追記する形で履歴を
残す。

記法（表に行を追記する。初期状態は記録なし）:

| 変更対象 TR 名 | 変更後の区分 |
|---|---|
| （記録なし） | — |

変更後の区分は、スコープ判定（スコープ内）に加え、スコープ内であれば優先・後続区分を併記する
（例: `スコープ内 / 後続スコープ`）。記録を追記したら、上の「スコープ判定」表の該当行も同じ区分へ
更新し、2 つの表が食い違わないようにする。
