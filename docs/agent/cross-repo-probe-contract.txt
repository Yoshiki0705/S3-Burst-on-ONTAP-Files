# Probe strings this repository registers against sibling repositories.
#
# Format: <repo>\t<cited path>\t<role>\t<probe>, sorted. One line per cited string. The probe is the
# last field and is taken whole, so it may contain anything except a tab. `#` starts a comment only at
# the beginning of a line -- a probe may contain one.
#
# The citing file on our side is deliberately absent: what the owner of a string needs is the set of
# strings not to reword silently, not our file layout. Matching the format
# FSx-for-ONTAP-Adoption-Playbook publishes, so a reader written for one works for both.
#
# Verified by `make outgoing-probes`, which reads each cited repository and fails when a registered
# string is gone. Hand-maintained rather than generated: a probe is a *chosen* claim-bearing substring,
# and there is nothing to derive it from.
#
# NOT BLOCKING ON A PULL REQUEST, AND THE CONDITION THAT WOULD CHANGE THAT.
#
# Resolving these strings means reading someone else's documents, so a failure usually means a sibling
# reworded something. Turning a pull request red for that teaches contributors to ignore red, so CI
# runs this offline -- reporting only that the contract parses -- and the scheduled job resolves the
# strings.
#
# The premise is the shape of this contract, not a preference. Stated in a form the checker verifies,
# because a premise that goes stale keeps justifying the decision it no longer supports:
#
#   SHAPE: 15 rows across 5 files, 5 in the largest.
#
# The two largest are translations of each other, so one rewrite of that errata can fail five rows at
# once: an other-caused red arrives as a batch that blocks every unrelated change until someone else's
# edit is reconciled.
#
# Revisit when that stops being true: rows spread across enough files that a single rewrite fails one
# or two.
#
# A sibling reached the opposite conclusion on that same reasoning and then reversed it, which is the
# reason this premise is checked rather than written once. They had described their contract as spread
# thinly, blocked on the strength of that, and found on counting that 13 of 22 rows sat in one file --
# so the shape they were relying on was not the shape they had. Do not cite another repository's shape
# from memory of what they said: count it, or do not use it.
#
# The gap this leaves is stated rather than hidden: `make all` catches a bad citation for anyone
# holding the sibling checkouts, and a contributor without them can merge a citation whose string was
# never resolved.
#
# AUDITED 2026-09-14 FOR THE OBSERVATION / INTERPRETATION SPLIT, AND IT FOUND ONE GAP.
#
# A cited sentence often carries a measurement and a conclusion drawn from it. Protecting only the
# measurement leaves the conclusion free to be withdrawn while this gate stays green -- and the
# conclusion is usually the part restated here, because it is what a reader acts on.
#
# The FPolicy errata's row reads "S3 AP 経由の操作は FPolicy 通知を**発火しない**ため、代わりにならない":
# one clause measured, one concluded. Only the first was registered, while four documents here say
# "FPolicy は代替にならない". The conclusion is now registered too, in both languages. Every other
# registered string was checked and carries its own claim whole.
#
# Applies to new rows as well: when a cited sentence has both, register both or say which half this
# repository restates.
#
# EXTENDED 2026-09-14 TO THE UNPUBLISHED DRAFTS, WHICH IS WHERE THE NEXT GAP WAS.
#
# The first pass read tracked documents only. The article drafts under `.private/` are gitignored but
# they are a publishing surface, and they cite four sibling documents this contract said nothing about.
# Two of them carry restated measurements and are now registered: the object-size ceiling being binary
# rather than decimal, and the rebalance states missing from the REST reference.
#
# Two are deliberately not registered, and the reasons differ:
#
#   * fsx-ontap-management-interfaces.md -- the endpoint reachability claim is quoted there from AWS's
#     own documentation, so a withdrawal on their side does not remove the basis for it here.
#   * solutions/amplify-portal/docs/verification-results.md -- what the draft describes is how that
#     document is organised, not a claim about behaviour. Nothing loses its evidence if it is
#     reorganised; the sentence just goes stale, and a probe would report the wrong thing.
#
# A sibling found this axis first, by noticing their own drafts restated more than their tracked docs.
#
# HOW TO ENUMERATE, BECAUSE THE FIRST PASS DID NOT AND STILL CALLED ITSELF AN AUDIT.
#
# That pass grepped the drafts for the three sibling repository *names*. It missed three cited
# documents whose URLs carry the local directory name instead -- and those URLs were 404, because the
# directory is not what the repository is called on GitHub. Grepping for what a citation ought to look
# like finds the citations that already look like that.
#
# Extract every URL and reduce it, rather than searching for the expected form:
#
#   grep -ohE 'https://github\.com/<owner>/[A-Za-z0-9._-]+/blob/[^)" ]+' .private/*.md | sort -u
#
# Then check each one resolves, and only then decide about probes. The three that turned up are cited
# from internal notes rather than from an article draft, so they stay out of scope by the publishing
# surface rule above -- but their links were wrong either way, which the name-based search could not
# have told anyone.
#
# role:
#   retraction  Expected to survive. Its absence means the claim moved or was retracted, and a claim
#               here has lost its evidence. Worth failing on.
#   reread      Quotes a minimum or maximum over a measured set, so adding a measurement rewrites the
#               string while the finding stands. Firing is "read this section again", not a
#               retraction. None registered yet -- no citation here rests on a range.
#
# TWO LIMITS, BOTH MEASURED BY THE OWNER OF THE STRINGS BELOW (their #401), AND NEITHER IS A DEFECT:
#
#   1. A probe passes when the string survives **anywhere in the file**, not where the claim is. Their
#      negative test changed one of two occurrences of a figure and the gate stayed green; only
#      changing both failed it. So a probe registered against a string that appears twice is weaker
#      than one registered against a unique string. `AP 経由の操作は**遮断されない**` below occurs
#      twice in its file and is registered anyway, because the alternative single-occurrence phrasings
#      of that claim span a line break.
#   2. A surviving string only says the sentence still exists. A claim **retracted but kept as
#      history** -- which this repository does deliberately, so a reader can see what was corrected --
#      keeps every probe against it green. **Registration is a floor, not a substitute for reading.**
#
# Line breaks matter for the same reason: a probe spanning one never matches. In the English errata the
# protocol list is split across two lines, so the registration below uses the single-line form further
# down the same file.
#
# A THIRD LIMIT, FOUND BY A DIFFERENT SIBLING RUNNING A CRITERION THIS REPOSITORY DID NOT HAVE.
#
# A probe that only ever matches a section *heading* cannot fire on the thing it was registered for. A
# heading keeps its title while the section beneath it is replaced with the opposite conclusion, so the
# claim can be withdrawn with every probe against it green. The replacement is rarely far away: it is
# usually the sentence directly below the heading, which is where the claim actually is.
#
# Independent of the multiplicity limit above, and neither subsumes the other. The heading-only cases
# against this repository each occur exactly once, so the multiplicity rule was silent on all of them;
# the multiplicity cases are figures repeated inside one measurement page, so a heading rule is silent
# on those. `make incoming-probes` and `make outgoing-probes` now report both, and count them.
#
# Reported, not failed, in both directions: the claim still resolves, and calling a fragile anchor a
# withdrawal would send the other side to look for a retraction that did not happen.
#
# A fourth kind is not decidable by rule and is left to the reader: a string too generic to be about
# the claim at all -- a product name, a section label. Length does not decide it. An eight-character
# measured ratio protects a great deal; a thirteen-character product name protects nothing.
#
# A FIFTH WAY TO STAY SILENT, OBSERVED BETWEEN TWO REPOSITORIES RATHER THAN REASONED ABOUT.
#
# A probe can stay green because the measurement it was waiting for was recorded **somewhere else**.
# The claim changed, the cited sentence did not, and nothing fired -- so the citing side kept
# publishing an instruction whose premise had been measured false.
#
# It happened with the single-connection range in perf-matrix-results.md. A sibling pinned that range
# and wrote, in their own citation table, that a block measurement landing there would move it. The
# block figures were measured and did not move it, because this repository had decided **before
# measuring** not to extend that table: its three rows say "similar values, different ceilings", and a
# figure at twice the ceiling does not belong in them. The decision was correct and is still in force.
# The defect was on the citing side, in predicting when a probe would fire: a prediction turns silence
# into confirmation that nothing has happened yet.
#
# Two rules follow, and the second is the one that generalises:
#
#   * Do not write when a probe is expected to fire. Register the string, state what it protects, and
#     read the result. There is no prediction anywhere in this contract, and there should not be.
#   * When a decision is *not to record something in a particular place*, that decision is itself
#     citable. A probe on the decision fires if the decision is reversed, which is the signal a
#     reader of the unchanged table actually needs. The sibling registered exactly that, and it is a
#     better anchor than the range it replaces.
#
# One trap while writing the above down: **quoting a pinned string verbatim, in the file it is pinned
# in, weakens the probe.** Explaining the arrangement in prose next to it took the sibling's new
# single-occurrence probe to two occurrences, and `make incoming-probes` reported it as weak on the
# next run. Describe the pinned claim, do not reproduce it. The gate catches this, which is the only
# reason it was a minute's work rather than a silent loss of protection.
#
